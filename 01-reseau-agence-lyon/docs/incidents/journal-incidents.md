# Journal des incidents — Réseau de l'agence de Lyon

Quatre incidents réels rencontrés pendant l'installation, puis trois pannes simulées pour l'exercice de diagnostic.

| N° | Date | Type | Symptôme | Cause | Correction | Enseignement |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 27/10/2026 | Réel | `apt update` sur srv-dns : échec de résolution de `archive.ubuntu.com` | Service NAT de VMware arrêté sur le PC hôte. `ping 8.8.8.8` renvoyait `Destination Host Unreachable` depuis l'IP de la VM elle-même : la passerelle `192.168.75.2` ne répondait pas | Redémarrage du service « VMware NAT Service », démarrage réglé en automatique | Une erreur de résolution de nom peut venir d'une coupure réseau : tester un `ping` vers une IP avant d'accuser le DNS |
| 2 | 27/10/2026 | Réel | Sur poste-lyon, `dig intranet.nordal.local` ne répond pas | Le poste a deux serveurs DNS (NAT et srv-dns) et envoyait les noms `nordal.local` au DNS du NAT, qui ne les connaît pas | Domaine `nordal.local` distribué par DHCP et accepté par le poste (`use-domains: true`) | Avec plusieurs cartes, il faut indiquer quel serveur DNS gère quel domaine |
| 3 | 27/10/2026 | Réel | `netplan apply` sur poste-lyon : `Cannot find unique matching interface for ens33` | La configuration netplan du clone désignait `ens33` par l'adresse MAC de srv-dns (`00:0c:29:44:af:ee`), alors que la carte du clone a une autre adresse (`00:0c:29:9f:d7:62`) | Suppression de l'identification par adresse MAC dans `00-installer-config.yaml` | Un clone garde la configuration réseau de sa machine d'origine |
| 4 | 27/10/2026 | Réel | Les deux VM reçoivent la même adresse IP sur `ens33` | `/etc/machine-id` identique sur les deux VM après le clonage : le DHCP du NAT les prend pour une seule machine | Nouvel identifiant sur poste-lyon (`systemd-machine-id-setup`), redémarrage, nouveau snapshot | Après un clonage Linux : changer le nom, la configuration réseau et le `machine-id` |
| 5 | 27/10/2026 | Simulé | poste-lyon n'ouvre plus l'intranet ; `dig` en `time out` alors que le `ping` du serveur passe | Serveur DNS du poste remplacé par `192.168.50.99` (`resolvectl status ens37`) | `resolvectl revert ens37`, puis renouvellement DHCP | `dig @<serveur attendu>` départage tout de suite le poste et le serveur |
| 6 | 27/10/2026 | Simulé | Le nom se résout, mais la connexion HTTP reste sans réponse | Règle `deny 80/tcp` dans ufw sur srv-dns | Suppression du refus, `allow 80/tcp` | Voir le [compte rendu détaillé](INC-2026-10-27-port-80-filtre.md) |
| 7 | 27/10/2026 | Simulé | Le nom se résout, mais vers `192.168.50.99` au lieu de `192.168.50.10` | Enregistrement erroné à la ligne 6 de `/etc/dnsmasq.d/nordal.conf` | Adresse corrigée, dnsmasq redémarré, cache DNS du poste vidé (`resolvectl flush-caches`) | Une réponse DNS doit être comparée à l'adresse attendue, pas seulement constatée |
